# LCEL: The Art of Chaining

## What is LCEL?

**LCEL** stands for **LangChain Expression Language**.

It is a declarative way to chain LangChain components together using the pipe operator (`|`). But why do we need a whole new "language" just to write Python code?

## 1. The Trap: Drowning in Glue Code

In the last lesson, we called the model directly: `model.invoke(text)`.
That works for a demo. It fails in production.

Why? Because a real AI feature is never just "call the model". It is a sequence of steps:

1.  **Format** the user input (Prompt Template).
2.  **Call** the model (LLM).
3.  **Clean** the output (Output Parser).

In standard Python, you write "Glue Code" to stick these together:

<CodeBlock
    codes={[{
        code: `def get_joke(topic):
    # Step 1: Glue the string together
    prompt = f"Tell me a joke about {topic}"
    
    # Step 2: Call the model
    response = model.invoke(prompt)
    
    # Step 3: Clean the result
    return response.content.strip()`,
        language: 'python',
        label: 'manual_glue.py'
    }]}
/>

This looks innocent. **It is a trap.**

What happens when you want to stream the output word-by-word? You have to rewrite the whole function.
What happens if you want to run 50 prompts in parallel? You have to write a complex definition with thread pools.

You end up writing more code to *manage* the flow than to *do* the work.

## 2. The Fix: The Magic Pipe `|`

If you have used the Linux command line, you know this symbol: `|`.

```bash
cat file.txt | grep "error" | sort
```

This operator tells the computer: **"Take the output of the left commands, and shove it into the input of the command on the right."**

LangChain borrowed this concept. We call it **LCEL** (LangChain Expression Language).

<CodeBlock
    codes={[{
        code: `chain = prompt | model | parser

chain.invoke("bears")`,
        language: 'python',
        label: 'lcel_chain.py'
    }]}
/>

This is not just shorter. It describes **what** we want to do, not **how** to do it.

## 3. Mental Model: The LEGO Assembly Line

Imagine a factory assembly line.

*   **Station 1 (Prompt)**: Takes raw plastic, molds it into a shape.
*   **Station 2 (Model)**: Paints the shape.
*   **Station 3 (Parser)**: Polishes the edges.

In LangChain, every "station" (Prompt, Model, Retriever) follows the **Runnable Protocol**. This means they all have the same "plugs".

Because the plugs match, you can snap them together like LEGO bricks.

## 4. Superpowers: Why We Do This

You might ask: *"Is this just syntactic sugar?"*

No. When you use the pipe `|`, LangChain effectively compiles your chain. Because it understands the structure, it gives you superpowers for free.

### Superpower A: Instant Streaming
You didn't write a generator? Doesn't matter. Since the chain knows how data flows, simply call `.stream()` instead of `.invoke()`.

<CodeBlock
    codes={[{
        code: `for chunk in chain.stream("cats"):
    print(chunk, end="", flush=True)`,
        language: 'python',
        label: 'stream.py'
    }]}
/>

### Superpower B: Parallel Batching
Need to generate 100 jokes? Don't write a loop. Just call `.batch()`. LangChain will spin up a thread pool for you automatically.

<CodeBlock
    codes={[{
        code: `chain.batch(["cats", "dogs", "fish"])`,
        language: 'python',
        label: 'batch.py'
    }]}
/>

## Summary

*   **Don't write Glue Code.** It breaks when you need features like streaming.
*   **Think in Pipelines.** Input connects to Output.
*   **Use the Pipe `|`.** It is the standard way to compose AI apps.
